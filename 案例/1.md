## 一、Nav2架构速览讲解
文档画出五层数据流：
1. **应用层**：RViz / Python脚本，发送目标点`NavigateToPose` Action请求给Nav2核心。
2. **Nav2核心节点（最重要）**
|节点|作用|
|---|---|
|`planner_server`|**全局规划**：根据地图，规划从起点到终点的整条路径|
|`controller_server`|**局部跟踪控制器**：照着全局路径输出速度指令，做局部避障|
|`behavior_server`|故障恢复Recovery，机器人卡住时执行原地旋转、清除代价地图等自救动作|
|`amcl`|粒子滤波**定位**，根据雷达+里程计，估算机器人在地图的位置|
|`map_server`|加载/提供地图文件|
|`nav2_lifecycle_manager`|生命周期管理器，控制上面这些节点按顺序启动、关闭|

3. **传感器与底盘层**
- 输入：激光雷达`/scan`、里程计`/odom`、点云`PointCloud2`
- 输出：速度指令`/cmd_vel`下发给机器人底盘

完整数据流：
`map_server加载地图` → `amcl做定位` → `planner_server生成全局路径` → `controller_server跟踪路径输出速度` → `behavior_server处理卡死异常` → `lifecycle_manager统一管控全部节点`

## 二、任务1.1：安装Nav2 + TurtleBot3仿真环境（⚠️Jazzy适配命令）
> ❌不要直接复制文档humble命令，全部包名替换jazzy

✅Ubuntu24.04执行：
```bash
sudo apt update
sudo apt install ros-jazzy-navigation2 ros-jazzy-nav2-bringup
sudo apt install ros-jazzy-turtlebot3* ros-jazzy-gazebo-* \
```

设置TurtleBot3模型环境变量（选burger小型机器人），写入`~/.bashrc`永久生效：
```bash
echo 'export TURTLEBOT3_MODEL=burger' >> ~/.bashrc
source ~/.bashrc
```

```bash
ros2 pkg list | grep nav2
```

## 三、任务1.2：启动Gazebo仿真
>新开终端，记得先source jazzy环境
```bash
source /opt/ros/jazzy/setup.bash
ros2 launch turtlebot3_gazebo turtlebot3_house.launch.py
```
预期现象：弹出Gazebo窗口，出现一个室内房间场景，里面有TurtleBot3 burger机器人，顶部带激光雷达圆盘、轮子、IMU传感器。

### 高频坑：Gazebo黑屏、闪退（Ubuntu24.04常见）
新开终端，先设置软件渲染环境变量，再启动仿真：
```bash
export LIBGL_ALWAYS_SOFTWARE=1
ros2 launch turtlebot3_gazebo turtlebot3_house.launch.py
```
>虚拟机/WSL运行仿真大概率需要开启这个软件渲染，性能会下降但是可以正常显示窗口。

## 四、任务1.3 RViz2查看机器人、传感器、TF坐标系树
Gazebo保持运行，**新开终端**：
```bash
source /opt/ros/jazzy/setup.bash
rviz2
```
RViz操作步骤：
1. 修改`Fixed Frame`（固定参考坐标系）：设置为`odom`或者`base_link`
2. 点左下角`Add` → `By Topic`，添加话题：
   - `/scan`：激光雷达点云数据（红色点）
   - `/imu`：IMU传感器数据
>刚启动仿真要等待10‑20秒，Gazebo加载模型，话题列表才会出现，不要刚打开就找话题。

### 查看TF坐标树（非常关键，导航全部依赖TF）
保持Gazebo运行，新开终端执行：
```bash
source /opt/ros/jazzy/setup.bash
ros2 run tf2_tools view_frames
```
程序会监听5秒TF数据，在当前目录生成`frames.pdf`文件。打开PDF，必须看到坐标链路：
`odom → base_link → base_scan`
- `odom`：里程计坐标系
- `base_link`：机器人本体中心坐标系
- `base_scan`：激光雷达传感器坐标系

>真机调试机器人第一步就是验证这条TF链路，仿真先把流程练熟。

✅阶段1全部验收标准：

2. RViz成功添加`/scan`雷达话题，看到点云
3. frames.pdf能看到`odom→base_link→base_scan`完整TF链路

## 五、加餐：一键启动Gazebo脚本（脚本化思想）
文档提供bash脚本，目的是不用每次敲一大串launch命令，同时把日志输出保存到文件，方便排错。
新建文件命名`gazebo_launch.sh`，复制下面脚本：
```bash
#!/usr/bin/env bash
set -e
LOG_DIR="$HOME/nav2_logs/$(date +%Y%m%d_%H%M%S)"
mkdir -p "$LOG_DIR"
echo ">>> 启动 Gazebo ..."
source /opt/ros/jazzy/setup.bash
ros2 launch turtlebot3_gazebo turtlebot3_house.launch.py \
> "$LOG_DIR/gazebo.log" 2>&1 &
echo $! > "$LOG_DIR/gazebo.pid"
sleep 5
echo ">>> Gazebo PID: $(cat "$LOG_DIR/gazebo.pid")"
echo ">>> 日志在 $LOG_DIR"
echo ">>> 关闭:kill $(cat "$LOG_DIR/gazebo.pid")"
```

给脚本执行权限，运行脚本：
```bash
chmod +x gazebo_launch.sh
./gazebo_launch.sh
```
- 仿真日志自动保存在`~/nav2_logs/时间戳/gazebo.log`，报错可以打开日志排查；
- 使用PID关闭仿真：`kill $(cat ~/nav2_logs/xxx/gazebo.pid)`
>这个脚本是骨架，阶段2会扩展它，一键同时启动Gazebo+SLAM+Nav2全套程序。

## 六、文档常见错误排查表（适配Jazzy）
|故障现象|原因|解决办法|
|---|---|---|
|`ros2 launch xxx` command not found|终端没有source ROS2|`source /opt/ros/jazzy/setup.bash`|
|Gazebo黑屏闪退|显卡/虚拟机OpenGL问题|`export LIBGL_ALWAYS_SOFTWARE=1`后再启动仿真|
|启动turtlebot3_gazebo launch报错|没设置`TURTLEBOT3_MODEL`|`echo 'export TURTLEBOT3_MODEL=burger' >> ~/.bashrc && source ~/.bashrc`|
|RViz有机器人模型，找不到`/scan`话题|Gazebo模型还没加载完|等待十几秒，再刷新Add话题列表|
|`view_frames`命令找不到|缺少tf2_tools包|`sudo apt install ros-jazzy-tf-transformations`|
